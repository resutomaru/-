# Перекуп-помощник — детальная спецификация (v1)

> **Статус:** блюпринт, кода ещё нет. Дополняет `site/index.html` (наглядная схема) и
> `docs/risk-register.md` (реестр рисков). Здесь — точные спеки по каждому модулю.
> **Чем глубже конкурента:** у каждого узла прописаны контракт (что на входе/выходе),
> предохранитель, метрика и измеримое «готово=», плюс честные пометки, где цена ещё не работает.
> Язык простой намеренно — чтобы понимал и заказчик, и разработчик.

---

## 0. Архитектура в одном абзаце

Две половины. **Завод** — автономный монолит, крутится сам 24/7, про клиентов не знает; делает «правду о товаре» (что это, почём, живое, не развод) и кладёт на **склад находок**. **Помощник** — свой у каждого клиента; берёт со склада нужное ему, доставляет карточкой, ведёт журнал и кабинет. Связь одна: **помощник читает склад в одну сторону.** Настройки клиентов — через Google-таблицы (мост). Рост (живость, продажа данных) — отдельно, на потом.

## 1. Глоссарий (простыми словами)

- **Лот** — одно сырое объявление с Авито.
- **Находка (enriched)** — лот, который завод опознал, оценил, проверил; лежит на складе.
- **Склад** — общая витрина готовых находок; единственная дверь между заводом и помощником.
- **Справочник моделей** — наш центральный список точных моделей, чтобы не путать «rx 570/580».
- **Ключ позиции** — короткий код модели для сравнения цен (напр. `rx580_8g`).
- **Обычная цена / медиана** — серединная цена по модели и региону (защита от шизо-ценников).
- **Светофор доверия** — 🟢/🟡/🔴 риск развода у конкретного объявления.
- **Дедуп** — защита от повторов (общий: «лот уже видели»; личный: «клиенту уже слали»).
- **Тихие часы / дайджест** — не пишем ночью; мелочь собираем в одно утреннее сообщение.
- **Теневой режим** — новое гоняем молча на реальных данных, смотрим датчики, потом включаем клиентам.
- **Рубильник цены** — переключатель «тест → боевой режим» в день оплаты доступа к Авито.

## 2. Принципы (спина, fail-safe)

1. **Тихо лучше, чем ложно.** Неуверенность → молчим/помечаем, не пушим.
2. **Падать безопасно.** Сбой → откат к последнему хорошему/осторожному, не к мусору.
3. **Изоляция взрыва.** Завод и помощник раздельны; баг в одном не валит другое.

## 3. Карта всех связей (словами)

Единственная «толстая» связь — склад. Остальное — служебное и одностороннее.

- **Завод → Склад:** готовая находка (контракт §4).
- **Склад → Помощник:** чтение находок (в одну сторону, только чтение).
- **Мост(Google-таблицы) → Помощник:** настройки клиента (фильтры, регион, пороги, тихие часы, chat_id).
- **Помощник → Мост:** статистика и журнал клиента (на запись в его таблицу/кабинет).
- **Кнопка «купил?» → Журнал / Автонастройка / Данные(обезличенно).**
- **Живость(Ф2) → Завод:** «лот продан/пропал», изменение цены (убрать со склада, пересчитать спрос).
- **Завод → Данные наружу (Ф2):** только обезличенные рыночные агрегаты.
- Клиентских правил/моделей в завод **не подаём** — завод чист.

## 4. Контракт «Склад находок» (центральная запись)

Что завод кладёт на склад и что помощник читает. Каждое поле — с честным флагом.

| Поле | Что это | Откуда |
|------|---------|--------|
| `id`, `source`, `url` | id, источник (rest-app/запасной), ссылка | Добыча |
| `posted_at`, `region`, `city` | когда и где выставлено | Добыча |
| `item_category` | gpu/cpu/ram/mobo/ssd/psu/other/assembly | Опознание |
| `model`, `position_key` | каноническая модель + ключ для сравнения | Опознание (+справочник) |
| `id_confidence` | уверенность опознания: высокая/низкая | Опознание |
| `price` | цена объявления | Добыча |
| `typical_price`, `discount_pct` | обычная цена и % ниже рынка | Оценка |
| `price_status` | **надёжно / мало данных / устарела / тест** | Оценка |
| `condition` | working / dead / unknown | Проверка |
| `trust`, `trust_reasons[]` | 🟢/🟡/🔴 + причины словами | Проверка |
| `velocity` | за сколько дней обычно уходит (если есть) | Живость (Ф2) |
| `liveness`, `checked_at` | live / sold / gone + когда проверяли | Завод/служебное |

**Правило fail-safe:** если `id_confidence`=низкая ИЛИ `price_status`≠надёжно ИЛИ `condition`=dead — находка **не может** уйти клиенту как «зелёная выгода». Максимум — в список с пометкой.

## 5. Модель данных (сущности, верхнеуровнево)

- **lots** — сырые объявления (завод).
- **finds** — находки на складе (контракт §4).
- **model_registry** — справочник канонических моделей и ключей.
- **price_stats** — обычные цены/медианы по (модель+регион), размер выборки, дата.
- **clients** — конфиг клиента: фильтры, регион, пороги, тихие часы, chat_id, активен.
- **deals** — журнал клиента: покупка/продажа/расходы/статус/навар.
- **sent_log** — личный дедуп (кому что слали).
- **seen_ids** — общий дедуп (какие лоты уже обработаны).
- **events/metrics** — датчики (для обнаружения дыр).
- **market_data** — обезличенные агрегаты на продажу (Ф2).

## 6. Модули — детально

Шаблон каждого: **ЦКП · Входы · Выходы · Внутри · Предохранители · Метрики · Готово= · Фаза.**

### 6.1 Завод · Добыча
- **ЦКП:** свежие объявления в общем складе-сырце, без потерь и без мусора-формата.
- **Входы:** rest-app (осн.), запасной сборщик (рез.).
- **Выходы:** сырые лоты → Опознание.
- **Внутри:** 1) поллинг раз в минуту; 2) адаптер приводит любой источник к единому виду; 3) проверка формата — кривые/неполные записи в карантин; 4) общий дедуп по id (один лот — один раз).
- **Предохранители:** RR-01 (датчик «нет лотов N мин» → тревога+переключение; карантин формата; потолок запросов), RR-15 (мониторинг бана).
- **Метрики:** лотов/мин, % в карантине, лаг с момента публикации, аптайм источника.
- **Готово=:** поток стабилен ≥24ч; формат-ошибки не попадают в базу; при обрыве источника авто-переключение < N мин.
- **Фаза:** 1 (осн.), запасной сборщик — 1→2.

### 6.2 Завод · Опознание (+ справочник моделей)
- **ЦКП:** у каждого лота проставлены категория и точная модель; мусор отсеян.
- **Входы:** сырые лоты.
- **Выходы:** находка с `item_category`, `model`, `position_key`, `id_confidence` → Оценка/Проверка.
- **Внутри:** 1) категоризатор по словам (наш канон v2.3) + исключения мусора (периферия/кулеры/карты памяти/БП-чужие); 2) ключ позиции по правилам (pk_*); 3) сверка с **центральным справочником моделей** → каноническая модель; 4) что не уверенно — `id_confidence`=низкая (в «деал» не пойдёт); 5) совсем кривое — дешёвый ИИ (Ф2).
- **Справочник моделей:** ведём мы (не клиенты). Засев — из наших же выгрузок (title→model→key). Обновляется централизованно.
- **Предохранители:** RR-03 (флаг уверенности; golden-набор; превью-дифф перед любым изменением словаря — без прохождения не катим), RR-12.
- **Метрики:** % опознанных, % с ключом (цель >90%), доля протечек в выборке-аудите.
- **Готово=:** на размеченной выборке протечки < заданного порога; новые правила не дают регрессов (golden зелёный).
- **Фаза:** 1 (категории/ключи/справочник), ИИ-дочитка — 2.

### 6.3 Завод · Оценка (цена)
- **ЦКП:** для модели в регионе известна обычная цена и честный флаг её надёжности.
- **Входы:** находки (модель+ключ), история цен.
- **Выходы:** `typical_price`, `discount_pct`, `price_status` → склад.
- **Внутри:** 1) медиана по (модель+регион) за окно; каскад: бренд+модель ≥ K лотов → иначе по модели; 2) **только рабочие** экземпляры, с отсевом выбросов (защита от опечаток и дохлых); 3) пересчёт раз в полчаса; 4) флаг: надёжно / мало данных (<K) / устарела (старше T) / **тест** (пока цены trial-фейковые); 5) кандидат на выгоду = цена ≤ обычная × (1 − N%); 6) «скидка > 70% = подозрительно» — не зелёное, на ручную проверку.
- **Предохранители:** RR-04 (мин. K; отсев выбросов; «ноль/протухло» не выдаём за выгоду; тест-режим до оплаты).
- **Метрики:** покрытие моделей ценой, размер выборок, доля «мало данных», (после оплаты) доля ложных «ниже рынка».
- **Готово=:** на реальных ценах (после рубильника) ложные «ниже рынка» < порога на размеченной выборке.
- **Фаза:** 1 — в тест-режиме; **рубильник** — в день оплаты Авито.

### 6.4 Завод · Проверка (состояние + светофор доверия)
- **ЦКП:** честная метка «рабочее/дохлое/непонятно» + риск развода у объявления.
- **Входы:** находки (заголовок+описание+поля продавца).
- **Выходы:** `condition`, `trust`, `trust_reasons[]` → склад.
- **Внутри (состояние):** dead-first консервативно (канон Ф4, экзамен 18/0/0); сомнение → unknown; спорное → ИИ (Ф2).
- **Внутри (светофор доверия):** правила по сигналам →
  - **🔴 текст (есть точно):** «только предоплата», «перевод на карту/перевод вперёд», «отправлю доставкой, оплата вперёд», «не звоните — пишите в вотсап/телеграм», описание скопировано 1-в-1.
  - **🟡 проверь:** новый продавец / мало отзывов / нет чека / «срочно уезжаю» + подозрительно дёшево.
  - **🟢 норм:** частник с историей, чек/гарантия/пломба, готов к проверке при встрече.
  - **Сигналы продавца** (возраст аккаунта, отзывы, тип, много одинаковых лотов) — **если отдаёт rest-app/сырой ответ** (надо подтвердить наличие полей). Фото-сигналы (стоковое/одно фото) — Ф2.
  - Перекос в осторожность: сомнение → жёлтый, не зелёный. Красное не прячем — показываем с предупреждением.
- **Предохранители:** RR-05 (golden dead→working=0), RR-06 (осторожный перекос; golden разводов; «купил→развод»→дообучение).
- **Метрики:** dead→working (=0!), пойманные разводы / ложные тревоги светофора.
- **Готово=:** состояние — экзамен зелёный на расширенном наборе; светофор — на размеченных разводах ловит ≥ цели при ложных тревогах ≤ цели.
- **Фаза:** 1 (текстовые сигналы + состояние), сигналы-продавца — 1 если есть поля, фото/ИИ — 2.

### 6.5 Завод · Служебное (надёжность)
- Перепроверка склада: лот продан/пропал → `liveness`=sold/gone, убираем из выдачи (RR-? / связано с Живостью).
- Флаги уверенности (`id_confidence`, `price_status`) — несут риск дальше, не теряются.
- Общий дедуп `seen_ids`.
- **Фаза:** 1 (базовая перепроверка перед выдачей), полная живость — 2.

### 6.6 Помощник · Фильтр клиента (+ ранжир)
- **ЦКП:** из общего склада — только то, что нужно ЭТОМУ клиенту, отсортированное по сочности.
- **Входы:** склад (чтение) + конфиг клиента (из моста).
- **Выходы:** отобранные находки → Доставка.
- **Внутри:** 1) жёсткие гейты: свежесть, не-dead, цена ≤ порога (когда цена надёжна); 2) фильтры клиента: категории, регион, цена, стоп-слова, мин-доверие; 3) ранжир выживших (свежесть, глубина скидки, доверие, спрос) — лучшее в пуш, остальное в дайджест.
- **Предохранители:** RR-07 (лимит пушей), RR-08 (client_id-изоляция), RR-09 (валидный конфиг).
- **Метрики:** находок/клиент/день, доля в пуш vs дайджест.
- **Готово=:** второй клиент с другим конфигом получает ДРУГОЙ набор (тест изоляции).
- **Фаза:** 1.

### 6.7 Помощник · Доставка-решение (карточка)
- **ЦКП:** клиент получает готовое к действию решение, а не просто ссылку.
- **Входы:** отобранные находки.
- **Выходы:** сообщение в Телеграм клиента; реакции (тапы) → Журнал/Автонастройка.
- **Внутри:** карточка = модель · цена/выгода* · навар* · состояние · 🟢🟡🔴 доверие · «уходит за N дней»* · «что спросить» · кнопки `[Написать продавцу]` `[Слежу]` `[Мимо]`. (`*` — зависит от реальных цен/живости, до того скрыто/в тесте). Тихие часы; утренний дайджест; личный дедуп; на старте — только свежее (без вывала склада).
- **Предохранители:** RR-07 (лимит/тихие часы/дедуп/анти-потоп), RR-08 (верный chat_id).
- **Метрики:** доставлено, открыто, тап «написать», жалобы/мьюты.
- **Готово=:** нет спама (в пределах лимита), нет повторов, нет ночных сообщений.
- **Фаза:** 1 (карточка без цены), ценовые строки — после рубильника.

### 6.8 Помощник · Кнопка «купил?» (петля обратной связи)
- **ЦКП:** знаем исход находки → кормим журнал, автонастройку и обезличенные данные.
- **Входы:** факт показа/интереса (тап).
- **Выходы:** ответ → Журнал; → Автонастройка; → Данные(обезличенно).
- **Внутри:** через время одно мягкое напоминание «Взял ту RX 580? [Купил][Не купил][Ещё думаю]». Один раз, без занудства. «Купил→брак/развод» = офлайн-сигнал на починку завода (пачкой, не живым проводом).
- **Предохранители:** не нагружает завод (живёт в помощнике); анти-занудство (одно напоминание).
- **Метрики:** доля ответов, конверсия в покупку.
- **Готово=:** ответ корректно заводит сделку в журнал и двигает настройку.
- **Фаза:** 1.

### 6.9 Помощник · Журнал-бухгалтерия (заменяет эксель перекупа)
- **ЦКП:** полный учёт прибыли перекупа без ручного экселя.
- **Поля сделки:** товар(модель), ссылка, дата покупки, цена покупки, **расходы** (доставка / ремонт-чистка / комиссия площадки / дорога-бензин / прочее), дата продажи, цена продажи, канал продажи, **статус** (в наличии / продано / возврат / в ремонте / списано), навар (=продажа − покупка − расходы), маржа %, дней в обороте.
- **Заполнение:** автозаполнение из находки по «Купил» (товар/цена/дата/ссылка — правишь, если торговался) · ручной ввод сделки, которой бот не находил · импорт старого экселя.
- **Дашборд:** прибыль за период, число сделок, % в плюс, средняя маржа, **сколько денег лежит в товаре** (оборотка), оборачиваемость (дней), топ/анти-категории, кэшфлоу по месяцам.
- **Выгрузка/синк:** в Google-таблицу/Excel (привычка остаётся).
- **Предохранители:** RR-10 (виден разбор закупка+расходы→навар; всё редактируемо; цену продажи НЕ угадываем; «оценка» и «факт» разной меткой).
- **Метрики:** доля занесённых сделок, % с проставленной продажей.
- **Готово=:** перекуп может вести ВСЮ бухгалтерию здесь и закрыть эксель.
- **Фаза:** 1 (ядро журнала + автозаполнение), импорт/графики — 1→2.

### 6.10 Помощник · Веб-кабинет
- **ЦКП:** личная страница: находки, журнал, статистика, модели/товары, настройки.
- **Входы:** данные клиента (БД) + его Google-таблица.
- **Внутри:** наглядная оболочка над теми же данными, что и в таблице («две двери — одни данные»).
- **Предохранители:** RR-08 (доступ только к своим данным).
- **Готово=:** клиент видит и правит всё своё, не видит чужое.
- **Фаза:** 1 (базовый: журнал+находки+настройки), расширения — 2.

### 6.11 Мост · Google-таблицы (конфиг под ключ)
- **ЦКП:** клиент сам крутит фильтры; подключение нового — за минуты.
- **Внутри:** у каждого своя таблица (фильтры + статистика + модели/товары). Система **синкает таблицу в быструю внутреннюю копию** по расписанию; бот в реальном времени читает копию (не саму таблицу). Новый клиент: шаблон-таблица → заполнил → заработало.
- **Предохранители:** RR-09 (валидация диапазонов; сломанная таблица → последние хорошие настройки + сигнал клиенту; бот не падает, если Google лёг).
- **Готово=:** правка в таблице доезжает в работу за ≤ интервал синка; кривой ввод не ломает бота.
- **Фаза:** 1.

### 6.12 Рост · Живость (Ф2)
- **ЦКП:** сигнал «продано/пропало» и скорость продаж (спрос).
- **Внутри:** расписание перепроверки лотов; «забиратель» как запасной сбор; «исчез/цена» → заводу; «спрос/скорость» → в оценку и ранжир.
- **Готово=:** проданные лоты не пушатся; есть оценка «уходит за N дней».
- **Фаза:** 2 (мини-версия «перепроверить перед пушем» — в 1).

### 6.13 Рост · Данные наружу (Ф2)
- **ЦКП:** продажа обезличенных рыночных сигналов (спрос/скорость/цены по моделям).
- **Предохранители:** RR-11 (только агрегаты при достаточном размере группы; личные сделки не продаём; согласие).
- **Фаза:** 2.

## 7. Датчики-метрики (как видим дыры заранее)

Точность находок · доля ложных «ниже рынка» · dead→working (=0) · пойманные разводы / ложные тревоги · % опознанных и с ключом · спам-рейт и жалобы · расход денег (запросы/ИИ) · аптайм источника · лаг обработки. Тревога на отклонении — раньше жалобы клиента.

## 8. Порядок стройки

- **Ф0 — фундамент:** always-on хостинг завода, секреты в хранилище, БД с бэкапами; разовый «догон данных» (категории+condition+ключи на все строки — закрыть NEW-3/E16).
- **Ф1 — без реальных цен:** Завод 6.1–6.5 (кроме боевой цены) → склад → Помощник 6.6–6.10 → Мост 6.11; дедупы, предохранители, датчики, теневой режим. Продукт уже полезен (опознание, состояние, доверие, журнал) без цены.
- **Рубильник:** оплата Авито → включаем боевую цену 6.3 → выгода/навар «загораются».
- **Ф2:** полная живость, ИИ на спорное/дефекты, массовый онбординг, продажа данных, подсказчик-переговорщик.

## 9. Открытые детали (нужен твой ввод, влияет только на цифры/поля, не на каркас)

1. **Цена:** значение порога N% по категориям (план: видео/проц/память/мать 40%, SSD/БП 55%), окно медианы (30 дней?), K (мин. выборка, план 8), порог «слишком хорошо» (70%?).
2. **Журнал:** финальный список расходов и статусов под твою практику (см. 6.9 — подтверди/дополни).
3. **Светофор:** какие поля продавца реально отдаёт rest-app (отзывы/возраст/тип) — определит, какие сигналы доступны в Ф1.
4. **Таблицы/кабинет:** точный список колонок-фильтров и колонок-статистики.
5. **Тихие часы / лимит пушей** — значения по умолчанию.

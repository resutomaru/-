# Слабые ключи — реестр R5-класса по ВСЕМ категориям (2026-06-11)

Мандат Алексея (11.06): «нужно чтобы все категории были ограничены от такого риска».
Риск R5-класса: **бакет-полочка, смешивающая товары с существенно разными ценами** → медиана-каша →
ложные «ниже рынка» в Ф6 (ось E17/E19, RR-03/RR-04).

**Принцип:** ключ существует ТОЛЬКО если он определяет ценовой класс товара. Не определяет → `null`
(«не уверен — молчим»; лот остаётся в базе, но не судится по цене и не становится находкой).

## Чистка ddr4-16gb (E19, 17.06) — форензика бакета

Бакет `ddr4-16gb` (no-speed) дал медиану 6300 → ложные «−52%» у бюджетных планок за 3000.
Построчный разбор 11 working: 9 честных 16GB (бюджет 3000 → премиум RGB 8000), **1 реальный мис-ключ**
(9999 = «2x16gb» 32 ГБ, в заголовке «16gb»), 12000 = вероятно 32 ГБ (IQR отрезает).
- **Корень №1 (НЕ лечится безопасно):** объём «2x16» только в описании; pk_ram читает заголовок/model.
  Лезть в описание за объёмом — опаснее (мусорные «2x…» дадут больше мис-ключей). Принято: оставляем, IQR.
- **Корень №2 (ИСПРАВЛЕНО):** частота «2666Hz»/«3200» в описании терялась → no-speed бакет.
  pk_ram += единица `hz/гц`. (Скорость-в-описании всё равно недоступна pk_ram — частичный фикс.)
- **Корень №3 (ДИЗАЙН, §4):** ключ без бренда/тира мешает бюджет+премиум → медиана завышена премиумом;
  бюджетный лот выглядит «находкой» против тир-смешанной медианы. Убрать мис-ключи: 6300→~6000 (мелочь).
  **Решение заказчика (РЕШЕНО 17.06 — вариант «а»):** принять §4-огрубление (статус-кво, больше выборки,
  светофор + K>20 + человек страхуют). Тир в RAM-ключ НЕ добавляем. Деплоен только фикс Hz/Гц.

Любое расширение словарей/ключей сверяется с этим реестром: новая форма ключа обязана отвечать
на вопрос «одинаково ли стоят товары внутри такого бакета?» — иначе null или явная запись сюда
как осознанное огрубление.

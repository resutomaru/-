# mini-app «Перекуп-помощник» — пилон 1 (каркас + онбординг)

Тонкий клиент: vanilla HTML/JS, без сборки. Вся логика на сервере (RPC). Auth — план Б:
`initData` Telegram прикладывается к каждому вызову, токен на клиенте не хранится.

## Файлы
- `index.html` — оболочка + авто-тема под Telegram + таб-бар (Главная/Находки/Журнал/Настройки).
- `app.js` — `rpc()`-хелпер, навигация, онбординг (`redeem_invite`), дайджест (`me` + `journal_dashboard`).
- `config.js` — `SUPABASE_URL` (проставлен) + `ANON_KEY` (вставить).

## Что показывает пилон 1
- Вход из Telegram → `me()`. Есть личность → **Главная** (привет + KPI журнала). Нет → экран **кода**.
- Код → `redeem_invite` → привязка личности → Главная.
- Вкладки Находки/Журнал/Настройки — заглушки (пилоны 2/3/5).

## Деплой — шаги
1. **Сервер:** прогнать `sql/api_auth_invite.sql` в Supabase (даёт `redeem_invite` + рефактор подписи).
   `bot_token` должен лежать в Vault (пилон 1c). Выпустить код: `insert into invite_codes (code, note) values ('PEREKUP-2026','первый');`
2. **Конфиг:** вставить `ANON_KEY` в `config.js` (Supabase → Project Settings → API → anon public; ключ публичный).
3. **Хостинг — Vercel (выбран):** vercel.com → Add New Project → импортировать репо `resutomaru/-` →
   **Root Directory = `app`** → Deploy → адрес `https://…vercel.app`. Вход через GitHub, бесплатно,
   авто-деплой при каждом пуше, работает и с приватным репо. Свой домен — позже в настройках проекта.
4. **BotFather:** боту «ПЕРЕКУП AI» → `/newapp` (или Bot Settings → Menu Button) → указать URL из шага 3.
   Кнопка-меню «Открыть приложение» появится в чате бота.
5. **Смоук-тест:** открыть mini-app из бота → если ты vovchik (личность засеяна) → Главная с твоим именем.
   Новый аккаунт без личности → экран кода → ввести `PEREKUP-2026` → Главная.

## Гейт пилона 1 (готово=)
`me()` возвращает vovchik в проде; чужой проходит онбординг по коду и получает СВОЮ личность; тема приложения
совпадает с темой клиента Telegram (светлая/тёмная). Далее — пилон 2 (лента находок).

## Безопасность
- В клиенте только публичный `ANON_KEY`. Bot-token/service-key — на сервере (Vault/n8n), не здесь.
- Доступ к данным стерегут `verify_initData` (подпись на каждый вызов) + RLS. Anon-key сам по себе ничего не открывает.
